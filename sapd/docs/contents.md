# 공공 AI 의사결정의 설계와 검증

**SAPD Framework: 상태 기반 적응형 정책의 이론, 검증, 거버넌스**

이석민 (한신대학교 공공인재빅데이터융합학)

---

## 도서 개요

### 핵심 질문
> 공공 영역에 AI 기반 의사결정 시스템을 도입할 때, **무엇을 설계하고 무엇을 검증해야 하는가?**

### 도서의 위치
- 기존 칼럼 2편이 **"왜 SAPD인가"**(이론적 정당화)를 다뤘다면, 이 도서는 **"그래서 어떻게 검증하는가"**(실무적 구현)까지 완결한다.
- SAPD Framework(이론층)와 Validation Module(실무층)을 하나의 체계로 통합하는 단행본.

### 독자
- 공공기관 AI 도입 담당자, 정책연구자, 대학원생
- AI 거버넌스·공공 데이터 분석 실무자
- 기술과 제도의 접점에서 의사결정 구조를 설계하는 사람

### 서술 원칙
1. **이론은 구현될 때 비로소 검증된다** — 프레임워크 제시에 그치지 않고, 각 장마다 진단 항목·체크리스트·평가 기준을 구체적으로 도출한다.
2. **기존 저서와의 차별** — 방법론(인과추론, ML/DL, LLM)은 이미 다른 저서에서 다뤘으므로, 이 도서는 **설계와 검증의 구조**에 집중한다. 분석 기법 자체가 아니라, 그 기법이 공공 의사결정에 투입될 때 충족해야 할 조건을 다룬다.
3. **한국 맥락의 구체성** — 국내 법·제도·사례를 중심으로 서술하되, 국제 기준(EU AI Act, OECD, NIST)과의 비교를 병행한다.

### 제1부 — 왜 적응형 정책인가: SAPD 이론 기초

> 제1부의 목적: SAPD가 왜 필요한지를 구조적으로 논증한다. EBP의 한계 진단 → 패러다임 전환 → 운영적 실현 가능성 증명의 3단계 논증.

---

#### 제1장. 증거 기반 정책의 구조적 한계

**핵심 논점**: EBP의 문제는 '증거'가 아니라 '시간 구조'에 있다.

| 절 | 내용 | 방향성 |
|---|---|---|
| 1.1 EBP의 성취와 전제 | EBP가 공공 의사결정에 가져온 혁신을 인정. 데이터 기반 객관성의 제도화. | 부정이 아닌 계승의 관점에서 출발 |
| 1.2 사후 평가의 함정 | 평가 시점에 환경이 이미 변화하는 구조적 시간 지연. Hood(1991) 후행적 평가 체계. 코로나19 정책 대응 사례. | 시간 구조의 문제임을 명확히 — 역량 부족이 아님 |
| 1.3 분절적 피드백 루프 | 정책-집행-평가-수정의 제도적 분리. Lindblom(1959) 점진적 조정. 각 단계의 독립적 시간 지연 누적. | 피드백 순환 주기 > 환경 변화 주기 → 구조적 실패 |
| 1.4 데이터 활용의 비연속성 | 실시간 흐름이 아닌 스냅샷 기반 의사결정. 보고서 매개의 이산적 정보 처리. | 세 가지 한계의 공통 근원 = 정태적 시간 모델 |
| 1.5 구조적 진단의 종합 | 세 한계가 동일한 근원(정태적 시간 모델)에서 파생됨을 정리. | 다음 장(패러다임 전환)으로의 논리적 전환점 |
| 1.6 AI 엔진의 불가피성 | EBP의 시간 구조 한계를 돌파하려면 실시간 상태 관찰·분석·피드백이 필요하며, 이는 AI 없이는 실현 불가능하다. AI가 적응형 정책의 엔진이 되는 것은 선택이 아닌 필연. 그러나 AI 엔진은 고유한 실패 모드(오류, 불투명성, 편향)를 수반한다 → 이 책의 제2~3부가 다루는 Validation Module의 필요성 선언. | **핵심 선언**: SAPD는 범용 프레임워크이나, AI 엔진 투입 시 추가 검증 레이어가 필수 — 이 책의 존재 이유 |

**기반 자료**: 칼럼 1편 「상태 기반 적응형 정책 개론」 §1

#### 제2장. 상태 기반 적응형 정책의 설계 원리

**핵심 논점**: 정책은 고정된 개입이 아니라 지능적 제어 논리이다.

| 절 | 내용 | 방향성 |
|---|---|---|
| 2.1 핵심 전환 — 개입에서 제어 논리로 | `Decision(t) = f(State(t))` 정식화. 상태 관찰, 동태적 의사결정 규칙, 피드백 루프 단축의 세 축. | SAPD의 정체성을 한 문장으로 확립 |
| 2.2 EBP와 SAPD의 구조적 비교 | 시간 모델, 데이터 형태, 의사결정 방식, 피드백 구조, 적응 방식, 설계 대상의 6차원 비교. | 증거를 부정하는 것이 아니라, 증거를 처리하는 시간 구조를 전환 |
| 2.3 수리적 기초와 지적 계보 | Bellman(1957) MDP, Simon(1969) 설계 이론, 베이지안 추론, 시스템 다이내믹스. | SAPD의 기여 = 수학의 발명이 아니라 공공 정책 설계로의 전환·적용 |
| 2.4 5대 레이어 아키텍처 | L1~L5 각 레이어의 기능, 핵심 질문, 상호 참조 구조. 순차적 절차가 아닌 동시적 층위. | 아키텍처의 전체상을 제시 — 이후 장에서 각 레이어를 심화 |
| 2.5 분석 도구군의 구조적 배치 | 인과추론, 베이지안, 시스템 다이내믹스, 시나리오 플래닝, 몬테카를로의 루프 내 배치. | 도구의 신규성이 아닌 배치의 체계성이 핵심 |
| 2.6 공공 가치의 아키텍처적 내재화 | 상태 변수 선택의 규범성, MDP와의 차별(보상 함수의 비자명성, 관찰 가능성의 정치학, 제도적 설계 제약), 민주적 책임성의 구체적 메커니즘. | 기술 도입론이 아닌 의사결정 아키텍처 설계론으로서의 정체성 |
| 2.7 SAPD Validation의 두 층위 | **범용 검증**(상태 정의·규칙 적절성·루프 작동·결과 개선)은 SAPD 자체의 검증이며, AI 없이도 성립한다. **AI 고유 검증**(오류·설명가능성·타당성·공정성)은 AI가 엔진으로 투입될 때 추가되는 검증 레이어다. 이 책의 Validation Module은 후자에 집중하되, 전자 위에 위치한다. | **구조적 선언**: SAPD Validation ⊃ AI-specific Validation. 이 책 = 안쪽 원(AI 고유 검증)에 집중 |

**기반 자료**: 칼럼 1편 §2~§5, 프레임워크 페이지

#### 제3장. 운영적 현실로서의 SAPD — 팔란티어 동형성 분석

**핵심 논점**: SAPD의 원리는 이론적 가능성이 아니라 이미 운영적 현실로 작동하고 있다.

| 절 | 내용 | 방향성 |
|---|---|---|
| 3.1 분석 목적과 방법 | 학술 프레임워크(SAPD)와 상용 플랫폼(팔란티어)의 구조적 비교 방법론. | 동형성 분석의 의의: 도메인 독립적 설계 원리의 존재 |
| 3.2 팔란티어 플랫폼 구조 | Foundry(데이터 통합·온톨로지) + AIP(AI·의사결정 자동화). 기술 스택 설명. | 기술 소개가 아닌 아키텍처 구조에 집중 |
| 3.3 순환 피드백 루프의 대응 | SAPD 4단계 루프 ↔ 팔란티어 4단계 운영 과정의 일대일 매핑. | State→Decision→Response→State(t+1) 구조의 보편성 |
| 3.4 5대 레이어와 기술 스택 매핑 | L1~L5 ↔ 온톨로지, 비즈니스 규칙, AIP Logic, Foundry, 학습 루프. 온톨로지의 이중 역할(L1+L5 관통). | 이론적 추상화와 기술적 실체화 사이의 체계적 대응 |
| 3.5 AI 역할 정의의 수렴 | 두 체계 모두 AI를 의사결정의 주체가 아닌 시스템의 구성 요소로 배치. | Human-AI 협업의 도메인 초월적 설계 원리 |
| 3.6 차이점 — 공공 가치의 설계 제약 | 시간 해상도, 내재적 가치, 확산 방식의 차이. 민주적 책임성·투명성·형평성은 SAPD 고유의 설계 제약. | 팔란티어가 증명한 것(운영 가능성) + SAPD가 추가하는 것(공공 가치) |
| 3.7 함의 — 이론과 구현의 상보성 | SAPD = Why & What, 팔란티어 = How. 향후 과제 도출. | 제2부(검증)로의 전환 — "작동 가능함은 보였다. 그렇다면 무엇을 검증해야 하는가?" |

**기반 자료**: 칼럼 2편 「SAPD Framework와 팔란티어 플랫폼의 구조적 동형성 분석」

### 제2부 — 공공 AI는 어디서 실패하는가: 검증의 필요성과 구조

> 제2부의 목적: SAPD 아키텍처에 AI가 투입될 때 발생하는 구체적 실패 유형을 식별하고, 각 실패에 대응하는 검증 체계를 구축한다. 제1부가 "왜 적응형인가"였다면, 제2부는 "적응형 시스템은 어디서 깨지는가"를 다룬다.

#### 제4장. 생성형 AI의 정책분석 오류 유형

**핵심 논점**: AI가 정책분석에서 틀리는 방식에는 구조가 있다. 오류를 분류해야 검증 기준을 설계할 수 있다.

| 절 | 내용 | 방향성 |
|---|---|---|
| 4.1 왜 오류 유형 분류가 필요한가 | "AI가 틀릴 수 있다"는 일반론을 넘어, 정책분석 맥락에서 **어떻게** 틀리는지를 구조화하는 이유. | 검증의 전제 = 오류의 구조적 이해 |
| 4.2 사실적 오류 (Factual Error) | 환각(hallucination), 출처 조작, 통계 수치 왜곡. 정책 근거의 사실적 기반이 붕괴하는 유형. | LLM의 확률적 생성 메커니즘에서 기인하는 구조적 한계 |
| 4.3 논리적 오류 (Logical Error) | 인과관계-상관관계 혼동, 생태학적 오류, 선택 편향의 간과, 반사실적 추론의 부재. | 저자의 인과추론 전문성 기반 — 정책분석에서 가장 치명적인 오류 유형 |
| 4.4 맥락적 오류 (Contextual Error) | 제도적 맥락 무시(법적 제약, 예산 구조, 이해관계자 역학), 시간적 맥락 탈락, 한국 고유 맥락의 미반영. | LLM의 범용성이 정책 맥락에서 약점이 되는 지점 |
| 4.5 프레이밍 오류 (Framing Error) | 문제 정의 자체의 편향, 대안 공간의 축소, 특정 가치 프레임의 암묵적 채택. | 가장 발견하기 어렵고 가장 위험한 오류 — 질문 자체를 왜곡 |
| 4.6 오류 유형 간 상호작용 | 사실적 오류가 논리적 오류를 강화하고, 맥락적 오류가 프레이밍 오류를 은폐하는 복합 패턴. | 단일 오류가 아닌 오류 체계(error system)로서의 이해 |
| 4.7 오류 유형별 진단 기준 도출 | 4가지 오류 유형 × 진단 질문 × 심각도 기준 → Validation Module 반영. | **실무 산출물**: 오류 유형 분류표 + 진단 질문 목록 |

**연결**: 이 장의 오류 분류가 제8장(루브릭 설계)의 평가 차원이 되고, MVP 프로토타입의 "신뢰도 표시" 기능의 설계 근거가 된다.

**저자 자산**: LLM 평가 논문 2편(LLM 문화적 정렬, LLM 앙상블 기반 토픽모델 평가), 42만건 텍스트 분석 경험.

#### 제5장. 설명가능성(XAI)의 공공적 재정의

**핵심 논점**: XAI는 기술적 투명성의 문제가 아니라, 공공 의사결정에서 "누구에게, 무엇을, 왜 설명해야 하는가"의 제도적 설계 문제이다.

| 절 | 내용 | 방향성 |
|---|---|---|
| 5.1 XAI의 기술적 계보 | DARPA XAI 프로그램, LIME, SHAP, Attention 시각화 등 기술적 접근의 발전사. | 기술적 배경을 간결하게 정리 — 이 도서의 주제는 기법이 아님 |
| 5.2 공공 영역에서의 설명가능성 재정의 | 기술적 설명(어떤 피처가 기여했는가) ≠ 공공적 설명(왜 이 결정이 정당한가). 설명의 대상(시민, 의회, 감사기관)에 따른 요구 수준 차이. | 설명가능성을 기술 문제에서 제도 설계 문제로 전환 |
| 5.3 국제 기준 비교 | EU AI Act의 투명성 요건, OECD AI 원칙, NIST AI RMF의 설명가능성 프레임. 각 기준의 구조와 적용 범위. | 한국 맥락 적용을 위한 국제 벤치마크 |
| 5.4 한국 공공 AI의 설명가능성 현황 | 국내 AI 윤리 기준, 공공기관 AI 도입 가이드라인, 실제 적용 사례와 공백. | 국제 기준과의 격차 진단 |
| 5.5 SAPD 아키텍처에서의 설명가능성 | L3(의사결정 아키텍처)의 감사 가능성 요건. `f(State(t))`의 각 구성 요소(변수 선택, 가중치, 임계값)에 대한 설명 의무. | 설명가능성을 SAPD 5대 레이어에 구조적으로 배치 |
| 5.6 설명가능성 진단 항목 도출 | 설명 대상별(시민/의회/감사기관/운영자) × 설명 수준별(입력/로직/출력/영향) 진단 매트릭스. | **실무 산출물**: XAI 진단 체크리스트 → Validation Module 항목 |

**연결**: 이 장의 진단 항목이 제9장(Validation Module 통합)의 설명가능성 차원을 구성한다.

**저자 자산**: XAI 기반 데이터 품질 진단 프레임워크 논문(SCOPUS 심사중), ML/DL 저서의 해석가능성 장.

#### 제6장. 정책분석 타당성 검증 체계

**핵심 논점**: AI가 산출한 정책분석 결과를 "어떤 기준으로" 검토할 것인가. 타당성의 구조를 정립해야 검증이 가능하다.

| 절 | 내용 | 방향성 |
|---|---|---|
| 6.1 정책분석에서의 타당성 개념 | 내적 타당성(인과적 식별), 외적 타당성(일반화), 구성 타당성(측정), 통계적 결론 타당성. | 인과추론 전문성을 정책분석 검증으로 확장 |
| 6.2 AI 기반 분석의 타당성 위협 | 데이터 편향에 의한 내적 타당성 훼손, 훈련 데이터 범위를 벗어난 외적 타당성 한계, 프록시 변수의 구성 타당성 문제. | 전통적 타당성 위협 + AI 고유의 위협을 통합 |
| 6.3 분석 질문의 구조적 검토 | "이 질문이 왜 모호한가", "효과 정의는 명확한가", "비교 집단은 적절한가", "인과적 해석이 가능한가". | MVP "질문 검토 AI"의 로직 근거 |
| 6.4 근거 추적과 출처 검증 | AI 출력의 근거 사슬(evidence chain) 추적 방법. RAG 기반 시스템에서의 출처 신뢰도 평가. | MVP "근거 출처 표시" 기능의 설계 근거 |
| 6.5 타당성 검증 프레임워크 | 타당성 유형별 × AI 오류 유형별(4장) 교차 검증 매트릭스. 검증 질문 목록. | **실무 산출물**: 정책분석 타당성 검증 체크리스트 |
| 6.6 SAPD 루프에서의 타당성 확보 | 일회적 검증이 아닌 순환적 검증 — State(t+1) 관찰을 통한 사후적 타당성 재검증. | SAPD의 적응형 피드백이 타당성 검증에도 적용됨을 보여줌 |

**연결**: 이 장의 검증 프레임워크가 제8장(루브릭)의 타당성 차원이 되고, MVP의 "질문 검토" + "검토 필요 지점 자동 표시" 기능의 근거가 된다.

**저자 자산**: 인과추론 전문가 수준(저서 2권, 이중강건 추정 논문), 평가방법론 저서.

### 제3부 — 무엇을 어떻게 검증할 것인가: Validation Module

> 제3부의 목적: 제2부에서 식별한 실패 유형들을 **체계적으로 진단하는 도구**를 설계한다. SAPD의 실무층(Validation Module)을 Draft v0.1에서 작동하는 v1.0으로 전환하는 것이 이 부의 핵심 과제.

#### 제7장. 공정성과 편향의 진단

**핵심 논점**: 공공 AI의 편향은 기술적 보정의 문제가 아니라, "누구의 현실이 시스템에 반영되는가"의 구조적 문제이다.

| 절 | 내용 | 방향성 |
|---|---|---|
| 7.1 편향의 다층 구조 | 데이터 편향(수집·표본·측정), 알고리즘 편향(모델·목적함수), 사회적 편향(역사적·제도적). 세 층위의 상호 강화. | 기술적 디바이어싱만으로는 해결 불가능함을 구조적으로 논증 |
| 7.2 공정성의 정의들 | 개인 공정성, 집단 공정성, 반사실적 공정성. 공정성 정의 간 수학적 비호환성(Chouldechova-Kleinberg 불가능 정리). | 공정성은 선택의 문제 — 어떤 공정성을 택할 것인가는 민주적 심의의 대상 |
| 7.3 공공 정책 맥락의 편향 사례 | 복지 수급 알고리즘, 범죄 예측, 채용 필터링 등 국내외 사례. 한국 맥락(지역, 성별, 연령, 장애) 특수성. | 추상적 논의가 아닌 구체적 사례 기반 |
| 7.4 SAPD에서의 편향 진단 위치 | L1(상태 변수 선택 시 누가 배제되는가), L2(성과 논리에서 어떤 가치가 우선되는가), L4(데이터 수집에서 누가 과소대표되는가). | 편향 진단을 SAPD 레이어별로 구조화 |
| 7.5 편향 진단 도구 설계 | 편향 유형별 × SAPD 레이어별 진단 매트릭스. 정량적 지표(통계적 패리티, 균등 기회 등) + 정성적 질문. | **실무 산출물**: 공정성·편향 진단 체크리스트 |

**저자 자산**: LLM 문화적 정렬 비교 논문(Jensen-Shannon 발산), AMICE 이중강건 인과추론 파이프라인.

#### 제8장. 공공 AI 평가 루브릭 설계

**핵심 논점**: 제4~7장의 개별 검증 차원을 하나의 통합 평가 도구로 조립한다.

| 절 | 내용 | 방향성 |
|---|---|---|
| 8.1 루브릭의 설계 원리 | 평가 루브릭이란 무엇인가. 수행 수준의 정의, 기준의 조작화, 평가자 간 신뢰도. | 교육학·평가학의 루브릭 이론을 공공 AI 맥락에 적용 |
| 8.2 평가 차원의 통합 | 오류 유형(4장) × 설명가능성(5장) × 타당성(6장) × 공정성(7장) → 4대 평가 차원. 차원 간 가중치 설계. | 개별 장의 진단 항목을 하나의 루브릭으로 조립 |
| 8.3 수행 수준 정의 | 각 차원별 4단계 수행 수준(미충족/부분 충족/충족/우수). 수준 간 경계의 조작적 정의. | 추상적 등급이 아닌 관찰 가능한 기준으로 정의 |
| 8.4 적용 시나리오별 루브릭 변형 | 도입 전 사전 검토용, 운영 중 모니터링용, 사후 감사용. 시나리오별 평가 초점과 가중치 차이. | 하나의 루브릭이 아닌 맥락 적응형 루브릭 체계 |
| 8.5 루브릭 검증 | 평가자 간 신뢰도 확보 방법, 파일럿 적용 설계, 루브릭 자체의 타당성 검증 절차. | 루브릭도 검증 대상임을 명시 |

**연결**: 이 장의 루브릭이 제9장(Validation Module)의 핵심 구성 요소가 되고, MVP 프로토타입의 "검토 필요 지점 자동 표시" 기능에 내장된다.

**저자 자산**: LLM 앙상블 기반 토픽모델 평가 프레임워크 논문, LDA vs LLM 성능 비교 논문.

#### 제9장. Validation Module 통합 아키텍처

**핵심 논점**: 제2~3부 전체를 하나의 작동하는 검증 시스템으로 통합한다. Draft v0.1 → v1.0.

| 절 | 내용 | 방향성 |
|---|---|---|
| 9.1 Validation Module의 설계 목표 | SAPD 이론층과 실무층의 관계. Validation Module은 SAPD를 "사용 가능한 도구"로 전환하는 인터페이스. | 이론 → 도구 전환의 명시적 선언 |
| 9.2 모듈 구조 | 4대 검증 차원(오류/설명/타당/공정) × 3대 적용 시나리오(사전/운영/사후) × SAPD 5대 레이어 → 3차원 검증 공간. | 전체 검증 체계의 아키텍처 |
| 9.3 체크리스트 통합 | 제4~8장에서 도출한 개별 진단 항목을 통합 체크리스트로 편집. 항목 간 우선순위와 의존 관계. | **핵심 실무 산출물**: 통합 Validation Checklist v1.0 |
| 9.4 프로토타입 연동 설계 | MVP(국회 회의록 분석 도구)에 Validation Module을 어떻게 내장하는가. 신뢰도 표시, 근거 추적, 검토 필요 지점 표시의 구현 설계. | 이론 → 코드 전환의 구체적 명세 |
| 9.5 적응형 검증 — SAPD 루프와의 통합 | 일회적 검증이 아닌 순환적 검증. State(t+1)에서 검증 결과가 갱신되는 구조. Validation Module 자체도 적응형. | SAPD의 핵심 원리(적응형 피드백)가 검증에도 적용 |
| 9.6 한계와 향후 과제 | v1.0의 범위 한정, 자동화 가능 항목과 인간 판단 필수 항목의 구분, 확장 로드맵. | 정직한 한계 인정 — 과잉 약속 방지 |

**연결**: 이 장이 도서 전체의 실무적 결론. 제1부(왜) → 제2부(어디서 실패) → 제3부(어떻게 검증) → 이 장에서 통합.

### 제4부 — 제도와 실행: 거버넌스에서 조달까지

> 제4부의 목적: Validation Module이 실제 공공 현장에서 작동하려면 제도적 환경을 이해해야 한다. 기술 도구를 제도적 맥락 안에 착지시킨다. **이 부는 저자가 새로 학습해야 하는 영역**이므로 조사·정리의 성격이 강하다.

#### 제10장. AI 거버넌스 제도 체계

**핵심 논점**: 공공 AI 도입 시 어떤 제도적 질문이 충족되어야 하는가.

| 절 | 내용 | 방향성 |
|---|---|---|
| 10.1 AI 거버넌스의 개념과 범위 | 거버넌스 ≠ 규제. 기술 거버넌스의 다층 구조(국제-국가-기관-프로젝트). | 거버넌스를 규제로 축소하지 않는 관점 |
| 10.2 국제 기준 체계 | EU AI Act(위험 기반 분류, 고위험 AI 요건), OECD AI 원칙, NIST AI RMF, UNESCO 윤리 권고. 각 체계의 구조·적용 범위·한계. | 국제 기준의 구조적 비교 — 나열이 아닌 분석 |
| 10.3 한국 AI 거버넌스 현황 | AI 기본법(제정 경과), 국가 AI 윤리 기준, 공공기관 AI 도입 가이드라인, 개인정보보호법과의 관계. | 현행 제도의 구조와 공백 식별 |
| 10.4 SAPD 관점에서의 거버넌스 재구성 | 정적 규제(사전 승인/사후 제재) vs. SAPD 적응형 거버넌스(상시 모니터링+적응적 대응). Validation Module이 거버넌스의 운영 도구가 되는 구조. | SAPD의 패러다임 전환이 거버넌스에도 적용됨 |
| 10.5 기관 수준 거버넌스 프레임워크 | AI 도입 기관이 갖추어야 할 거버넌스 구조: 의사결정 체계, 위험 관리, 모니터링, 문서화. | **실무 산출물**: 기관 AI 거버넌스 체크리스트 |

**저자 상태**: 새로 학습 필요. 프레임워크에 언급 수준 → 제도적 언어로 체계화.

#### 제11장. 공공 AI 책임 구조

**핵심 논점**: AI가 결정했을 때 누가 책임지는가. 자동화된 행정 결정의 책임 귀속 구조.

| 절 | 내용 | 방향성 |
|---|---|---|
| 11.1 책임의 다층 구조 | 개발자-운영자-의사결정자-감독기관의 책임 분배. 알고리즘적 의사결정에서의 책임 공백(responsibility gap). | 기술적 문제가 아닌 제도 설계 문제로서의 책임 |
| 11.2 자동화된 행정 결정의 법적 쟁점 | 행정절차법, 행정기본법(자동적 처분 조항), 개인정보 자동화 결정 거부권. 한국 법제의 현황과 한계. | 법적 근거와 실제 적용의 격차 |
| 11.3 국제 비교 — 책임 설계 사례 | EU의 인간 감독 요건, 캐나다의 알고리즘 영향 평가(AIA), 뉴질랜드의 알고리즘 헌장. | 제도 설계의 선진 사례에서 구조를 추출 |
| 11.4 SAPD에서의 책임 배치 | L3(의사결정 아키텍처)에서의 책임 노드 설계. 의사결정 함수 f의 각 단계에 책임 주체를 매핑. | 책임을 아키텍처 수준에서 설계 — 사후 추궁이 아닌 사전 배치 |
| 11.5 책임 구조 설계 가이드 | 기관이 AI 도입 시 책임 구조를 어떻게 설계할 것인가. 책임 매트릭스 템플릿. | **실무 산출물**: AI 책임 구조 설계 템플릿 |

**저자 상태**: 새로 학습 필요. SAPD 프레임워크의 민주적 책임성 원칙을 제도적 언어로 구체화.

---

#### 제12장. 공공조달과 서비스 설계

**핵심 논점**: SAPD + Validation Module을 공공 현장에 실제로 투입하기 위한 제도적 경로.

| 절 | 내용 | 방향성 |
|---|---|---|

Phase 1 (2026.03~06) — MVP와 동시 진행:
1. **제4장** (오류 유형) → 프로토타입 "신뢰도 표시" 설계 근거

3. **제6장** (타당성) → 프로토타입 "질문 검토" 설계 근거

Phase 2 (2026.07~10) — Validation Module 구현과 동시:
4. **제7장** (공정성) → Validation Module 평가 항목
5. **제8장** (루브릭) → Validation Module 평가 체계
6. **제9장** (통합) → Validation Module v1.0

Phase 3 (2026.11~2027.02) — 서비스 준비와 동시:
7. **제10장** (거버넌스) → 서비스 제도적 맥락
