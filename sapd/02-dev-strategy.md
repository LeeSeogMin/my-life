작성일: 2026-03-12

## 첫 번째 과제: 국회 회의록 분석 + 질문 검토 AI

### MVP 기능 5개
1. 회의록 업로드 → 쟁점 자동 추출
2. 쟁점별 찬반 입장 구조화
3. 분석 질문 입력 → "이 질문의 한계" 피드백
4. 답변에 신뢰도·근거 출처 표시 (Validation Module)
5. "추가 검토 필요" 지점 자동 표시

기능 1~2: 서비스 A (문서 분석)
기능 3: 서비스 B (질문 검토)
기능 4~5: Validation Module 내장

### 기술 스택
- 데이터: 국회 회의록 API 또는 크롤링 (공개 데이터)
- 백엔드: Python (LangChain/LlamaIndex) + RAG
- 프론트: Next.js (기존 홈페이지 연동 또는 별도)
- LLM: Claude API 또는 GPT API
- DB: Supabase (기존 인프라 활용)

### 단계별 전략

```
Phase 1 (2026.03~06): 상업용 API (Claude/GPT)
  → 공개 데이터(국회 회의록)로 MVP 빠르게 구현
  → 속도 우선, 품질 검증

Phase 3 이후 (2026.11~): 오픈소스 폐쇄형 추가
  → 기관 내부 문서 처리용
  → 후보: Llama, Qwen, EXAONE 등
  → 자체 서버 또는 프라이빗 클라우드 배포
```

| 서비스 | 제공 기관 | 주요 기능 | 한계 |

### 기존 서비스에 없는 것 = 우리의 차별점

기존 서비스는 모두 **"검색·요약·열람"** 수준이다. 다음 3가지가 시장에 부재:

1. **쟁점 구조화** — 회의록에서 찬반 입장을 자동으로 구조화하는 도구 없음
2. **분석 질문 검토(심문)** — "이 질문이 왜 모호한지, 무엇이 더 필요한지" 지적하는 도구 없음
3. **타당성 검증 내장** — 신뢰도 표시, 근거 추적, 검토 필요 지점 자동 표시 없음

### 포지셔닝

```
기존: 회의록 검색·요약 도구 (무엇을 말했는가)
우리: 회의록 쟁점 구조화 + 분석 질문 심문 + 검증 표시 도구 (무엇이 쟁점이고, 이 분석이 타당한가)
```

이 차별점이 곧 SAPD Validation Module의 실무 적용 사례가 된다.

## 서비스 제공 전략

### 무료 제공 (Phase 1~2)

| 목적 | 설명 |
|------|------|
| Coming Soon 탈출 | 홈페이지에 "작동하는 도구"가 생김 |
| 사용자 피드백 | 어디서 막히고, 뭘 기대하고, 어디서 틀리는지 파악 |
| 포트폴리오 | 서비스 제안 시 "이미 만들어본 경험" 증명 |
| 교육 도구 | 서비스 3(교육)에서 실습 자료로 활용 |
| 연구 데이터 | 사용 로그가 논문 데이터가 됨 |

### 유료 전환 (Phase 3 이후)

```
무료: 국회 회의록 분석 도구 (공개 데이터, 상업용 API)
  → 사용자 확보 + 피드백 + 실적

유료:
  → 서비스 1: 기관 내부 문서 대상 AI 사전 검토 (컨설팅)
  → 서비스 2: 맞춤형 분석 시스템 설계 (프로젝트)
  → 서비스 3: 교육·워크숍 (강의료)
```

무료 도구가 유료 서비스의 영업 도구가 된다.

## MVP 이후 고도화 분석 기법 로드맵

### Tier 1 — 이미 보유한 역량으로 바로 추가 가능

| 기법 | 내용 | 보유 역량 근거 |
|------|------|---------------|
| 토픽 모델링 | 회의록 전체에서 주요 정책 의제 자동 분류 (BERTopic, LDA) | 토픽모델 비교 논문 2편, 저서 |
| 감성·입장 분석 (Stance Detection) | 발언자별 찬성/반대/중립 자동 분류 | NLP 42만건 분석 논문 |
| 발언자 네트워크 분석 | 누가 누구에게 반박하는가, 정당 간 대립 구조 시각화 | 빅데이터 저서 (네트워크 분석) |
| 시계열 의제 추적 | 특정 정책 이슈의 시간에 따른 변화 | TimeGPT, 시계열 분석 저서 |
| 인과추론 연결 | 정책 논쟁이 실제 정책 결과에 영향을 미쳤는가 | DID, PSM, AIPW 논문 |

### Tier 2 — 약간의 추가 설계로 가능

| 기법 | 내용 | 필요한 것 |
|------|------|----------|
| 논증 마이닝 (Argument Mining) | 발언에서 주장·근거·반박 자동 추출 | 프롬프트 설계 + LLM 파이프라인 |
| 프레이밍 분석 (Frame Analysis) | 같은 이슈를 어떤 프레임으로 말하는가 | 토픽모델 + 분류기 조합 |
| 숙의 품질 평가 (Deliberation Quality) | 토론이 얼마나 근거 기반인지 점수화 | 평가 루브릭 설계 (Validation Module 연장) |
| 교차 문서 쟁점 매핑 | 여러 회기에서 동일 쟁점의 입장 변화 추적 | RAG + 벡터DB 확장 |

### Tier 3 — 장기적 연구 개발

| 기법 | 내용 | 필요한 것 |
|------|------|----------|
| Human-AI Deliberation | AI가 토론을 중재하고 합의점 도출 | 멀티에이전트 시스템 |
| 정책 시뮬레이션 연결 | 분석 결과를 디지털 트윈·에이전트 시뮬레이션에 입력 | SAPD Layer 4~5 구현 |
| 실시간 적응형 분석 | 진행 중인 회의를 실시간 분석 | 스트리밍 파이프라인 |

### 버전별 로드맵

```
MVP (Phase 1): 쟁점 추출 + 질문 검토 + 검증 표시
v2.0 (Phase 2): + 토픽 모델링 + 입장 분석 + 네트워크 시각화
v3.0 (Phase 3): + 논증 마이닝 + 숙의 품질 평가 + 시계열 추적
v4.0 (Phase 4): + 인과추론 연결 + 정책 시뮬레이션
```

Tier 1은 교수님이 이미 논문으로 입증한 기법들이므로 MVP 직후 바로 추가 가능.
