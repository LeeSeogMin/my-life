## 전제: 역량 재평가 결과

이미 보유한 역량 (저서 6권, 논문 6편, 8과목 강의로 입증):
- 인과추론·계량경제학: **전문가 수준**
- LLM·RAG·멀티에이전트: **교재를 쓸 수 있는 수준** (저서 16장)
- ML/DL·NLP: **상급~전문가**
- 시스템 설계: **상급~전문가** (SAPD 5계층 + 팔란티어 비교)

**따라서 "공부"가 아니라 "구현과 체계적 문서화"가 핵심 과제다.**

새로 학습이 필요한 것은 2개뿐:
- AI 거버넌스 제도 언어 (국내외 규제 체계)
- 공공조달·검토 절차 (기관 대상 서비스 진입)

## 핵심 원칙

**이미 아는 것을 전문 문서로 체계화하고, 동시에 도구로 구현한다.**

```
보유 지식 → 전문 문서(docs/) → 칼럼 변환(columns/) → 홈페이지 발행
                   ↕ 동시 진행
           프로토타입 개발(dev/) → 홈페이지 공개
```

### 작업 흐름

1. **전문 문서 작성** (`docs/`): 이미 보유한 지식을 도서 수준으로 체계화 — 학술적 근거, 프레임워크 설계, 국제 기준 비교 포함
2. **칼럼 변환** (`columns/`): 전문 문서의 핵심을 대중이 읽을 수 있는 칼럼으로 변환 → 홈페이지 `/writing`에 발행
3. **프로토타입 개발** (`dev/`): 문서화와 병행하여 실제 작동하는 도구 구현
4. **상호 피드백**: 개발 과정에서 발견한 문제가 문서를 보강하고, 문서의 기준이 개발에 반영됨

### 산출물 5개

한 번의 주제 작업이 5개의 자산이 된다:
1. 전문 문서 (도서/논문 수준 원고)
2. 칼럼 (홈페이지 Writing)
3. Validation Module 항목 (프레임워크)
4. 프로토타입 검증 로직 (서비스 차별화)
5. 서비스 산출물 템플릿 (서비스 준비)

### 실제 병목 3개 (이것을 해결하는 것이 이 계획의 목적)

1. **프로토타입이 없다** — Coming Soon 3개, 작동하는 도구 0개
2. **Validation Module이 구현되지 않았다** — 설계 초안만 있고 실제 도구 없음
3. **서비스 경험이 없다** — 기관 대상 실무 서비스 실적 0건
